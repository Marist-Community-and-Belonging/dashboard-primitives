# Dashboard service

The Marist IPEDS Benchmark Dashboard is a Go service using Gin to serve a static D3 interface and versioned data endpoints. All browser assets and five final IPEDS collections are embedded in the compiled binary.

The reusable design, chart, interaction, data, accessibility, and LLM implementation specification is documented in [`../docs/dashboard-design-system.md`](../docs/dashboard-design-system.md).

## Run locally

```sh
go run .
```

Open `http://localhost:8080/`. Set `DASHBOARD_ADDR` to change the listening address.
Request logs use Go's `log/slog` package and include a compact timestamp,
method, path, status, and duration. Interactive terminals color each line by
level; redirected logs remain plain. Set `DASHBOARD_LOG_LEVEL` to `debug`,
`info`, `warn`, or `error`.

## Verify

```sh
go test -race -cover ./...
go vet ./...
go build -o bin/dashboard .
```

From the repository root, `make test-go` runs the same race-enabled Go test
suite. Pull requests and dashboard changes run tests, vet, and a build in
GitHub Actions.

For public deployment, terminate HTTPS at a reverse proxy or CDN and enable
gzip or Brotli there. Embedded static assets carry one-hour cache headers.

## Backend layout

- `application.go` loads configuration, pages, and datasets at startup.
- `pages.go` is the static page registry. Add a route and embedded HTML file
  there to expose another dashboard page.
- `resources.go` owns the reusable year-versioned JSON/CSV collection loader.
- `api.go` registers the versioned HTTP API.
- `middleware.go` owns request logging, recovery, and related HTTP
  behavior.
- `server.go` assembles the router; `main.go` owns process startup and graceful
  shutdown.

Dataset routes use one generic loader, selector, and response implementation.
Adding another dataset requires its schema/export function, one loader
definition in `application.go`, and one route registration in `api.go`.

## Refresh a final IPEDS collection

From the repository root, run:

```sh
python3 scripts/ipeds/refresh.py --year 2024
```

Use the collection start year. The command checks the official NCES Access release page and stops if that collection is not marked final. Once final, it downloads the required official Complete Data File archives, verifies and records checksums, normalizes older raw tables when a derived file is unavailable, updates the release manifest, and regenerates all four public datasets. Rebuild the Go binary afterward so the new collection is embedded.

## Endpoints

- `GET /api/v1/health`
- `GET /api/v1/overview/releases`
- `GET /api/v1/overview`
- `GET /api/v1/export.csv`
- `GET /api/v1/diversity-access`
- `GET /api/v1/diversity-access/export.csv`
- `GET /api/v1/success-equity`
- `GET /api/v1/success-equity/export.csv`
- `GET /api/v1/affordability-resources`
- `GET /api/v1/affordability-resources/export.csv`

Pass a validated collection year to any data or export endpoint with the `year` query parameter. The no-parameter form serves the latest embedded final collection.

The browser changes years in place through these APIs, updates the URL without a page reload, and preserves the selected year across section navigation. Newly rendered cards and charts animate once as they first enter the viewport. Reduced-motion preferences disable the presentation timing.

The `/marist-profile` page assembles the existing versioned endpoints into a Marist-only selected-year profile and six five-year institutional trends. It introduces no hand-edited data or separate source of truth, so newly refreshed final collections appear automatically.

The public datasets under `web/data/` are generated by the scripts under `../scripts/ipeds/`, including `build_success_equity.py` and `build_affordability_resources.py`. Do not edit them by hand.

Metric definitions and `favorable_direction` rules live in `../data/config/`. The browser adds a small positive tag only when Marist is objectively above the peer median for a higher-is-favorable measure or below it for a lower-is-favorable measure. The tag states the exact difference. Results that do not meet the configured comparison remain visible without a tag.
